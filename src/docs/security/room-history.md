# 房间

在 Matrix 中，所有对话都发生在房间里。每个房间至少有一个成员，成员各自拥有不同的权限。房间同时保存消息记录和各类用户事件；加密房间中的对话是安全的，Matrix 为此设计了复杂的机制，对房间历史记录尤其如此。作为房间管理员，您可以控制历史记录对谁可见，也可以把房间历史导出成文件，做更细致的处理。

## 房间的公开性与加密性

Matrix 中的房间有公开性和加密性两个属性：公开房间不能加密，私密房间则可以选择是否开启加密。

在加密房间中发送的任何类型消息都会端到端加密，除您和目标设备之外，没有第三方能获取聊天明文。公开房间任何人都能搜索并加入，私密房间则搜索不到——无论它是否开启加密。加密房间只能通过邀请加入。此外，Matrix 不建议在公开房间中开启加密：除了消耗参与者设备的性能外没有任何好处——只要加入房间，任何人都能看到房间里的消息。

私密房间和公开房间之间可以互相转换，但未加密房间一旦转为加密房间，就无法再改回未加密状态。

## Matrix房间与QQ/微信群的区别

Matrix 房间与 QQ / 微信群的最大区别，就是它要么是公开的——任何人都可以不打招呼直接加入，要么是隐藏的——除非收到邀请，否则谁也无法加入，甚至无法通过搜索发现您加密房间的存在。

另一处区别是权限：Matrix 房间的成员权限可以细致配置，而不只是简单的群主、管理员两档。

## 房间的名字

Matrix 用户名形如 `@username:example.server.com`，其中 example.server.com 是服务器地址，在 NerChat! 里就是 `chat.neboer.site`。房间的名字则形如 `#roomname:chat.neboer.site`：开头的“#”表示这是一个房间别名，用户名的开头则是“@”。

和用户名一样，房间别名相当于房间的 ID，用来定位一个房间。一个房间可以有多个别名，先到先得、不能重名，其中必须选一个作为主要别名，也就是房间的“正式名字”。在“房间设置 - 通用”中，可以添加“本地地址”作为别名，再到“已发布的地址 - 主要地址”里指定其中一个作为房间的正式名字；您还可以选择把主要地址发布到我们服务器的房间目录，这样别人浏览服务器房间列表时就能直接加入您的公开房间。

## 加密房间的聊天历史

在加密房间中，聊天历史都是加密的。服务器只会把加密后的房间历史发送给客户端，解密工作由客户端完成。

在加密房间中，您可以自由控制消息历史记录对新成员的可见性。打开“房间设置 - 隐私安全 - 谁可以阅读历史消息”，可以调整以下选项：

- 选择“任何人”：在加密房间中等价于“仅成员（从选中此选项时开始）”；在公开房间中则表示允许未加入的用户浏览全部历史聊天记录。
- 选择“仅成员（从选中此选项时开始）”：此后只要是房间成员，就能看到全部聊天记录，最方便，也最不安全。
- 选择“只有成员（从他们被邀请开始）”：除非主动邀请某人，否则即使他加入了房间，也看不到邀请之前的聊天记录。
- 选择“只有成员（从他们加入开始）”：每个人只能看到自己加入房间之后的聊天记录。如果需要防止新用户看到房间里的旧消息，这是最安全的选择。

注意，修改这些选项不会改变已有历史消息的可见性：比如之前设为“任何人”，之后改成“只有成员（从他们加入开始）”，新加入的成员仍然能看到调整之前房间的全部聊天记录。

## 加密房间的安全性

在加密房间里，只有当所有成员的设备都通过了您的交叉认证、状态为“安全”，这个房间才称得上安全。当房间处于完全安全的状态时，聊天框左侧会出现一个小小的绿色盾牌，表示端到端加密得到了完整保证。一旦有不受信任的陌生设备加入会话，聊天的安全性就不再成立，盾牌状态也会随之改变——这正是它的作用。详细内容可以参考[交叉认证方法](cross-sign#交叉认证方法)。
